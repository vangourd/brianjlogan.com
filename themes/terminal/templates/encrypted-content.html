$ how this works

  • → the key stays in the URL fragment. The link uses #slug.key, not a query parameter. Browsers don't send the fragment to the server, and the page removes it from the address bar after loading.
  • → the article is decrypted in your browser. Each encrypted file uses AES-GCM with a random salt and IV. A wrong key fails authentication instead of producing unreadable content.
  • → the slug isn't the secret. Encrypted files live at /encrypted-newsletters/<slug>.bin; the key is what protects the contents. Use a long, randomly generated key.
